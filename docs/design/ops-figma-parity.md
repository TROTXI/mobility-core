# Ops Figma implementation ledger

Source: Trotxi Ops — Off Purple UI/UX Design & Prototype, pages 05–20. This ledger separates working pilot features from visual concepts; a frame existing in Figma does not by itself authorize a new operational policy.

The Figma cover calls pages 05–12 cleaned source references, pages 13–18 provisional module patterns pending review, and pages 19–20 companion/prototype work. The website remains a React Ops console, not a mobile app. Its shared shell uses the off-purple dark/light palette, compact rail, top bar, and responsive companion layout.

The Ops trip manifest is `GET /v1/ops/trips/{id}/manifest`. It is admin-only, reauthorizes against current database facts, returns a complete maximum-500-rider snapshot, signs private avatars for 120 seconds, and never exposes object keys. The driver manifest remains assigned-driver-only.

Pilot scope decision, 2026-09-24: exclude route optimisation and implement approved pilot workflows only. Provisional frames and any depicted workflows without an approved API/policy are references for later review, not launch requirements. The manually configured route path is part of the already approved route-version publishing workflow; every leg requires explicit operator confirmation, and the browser computes WGS84 distances along that path before sending the reviewed geometry contract.

Before calling pilot visual parity complete: perform the requested browser walkthrough in dark, light and responsive layouts. Do not describe a provisional frame or an untested mock as a working feature.
