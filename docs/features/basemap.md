# Basemap

We host our own map tiles. No Google Maps, no Mapbox, no per-request billing, and
no vendor that can reprice us once riders depend on the map.

The pipeline has four parts. Three exist; one does not yet.

| Part               | What it is                                                | State                  |
| ------------------ | --------------------------------------------------------- | ---------------------- |
| Tile archive       | `ghana.pmtiles`, OSM data through the OpenMapTiles schema | Live                   |
| Styles             | How clients draw those tiles, light and dark              | Built, needs uploading |
| Glyphs             | Font atlases for text labels                              | **Missing**            |
| Client integration | MapLibre in the two apps and the ops console              | #180, #170             |

## The tile archive

Built with [planetiler](https://github.com/onthegomap/planetiler) from the
Geofabrik Ghana extract and uploaded to Cloudflare R2, served at
`https://tiles.trotxi.com/ghana.pmtiles`.

```
format      PMTiles v3, clustered, gzip, MVT vector
zoom        0 to 14
bounds      lon -3.807 to 1.394, lat 3.704 to 11.178
schema      OpenMapTiles 3.16.0, 16 vector layers
size        101 MB, 79,193 addressed tiles
```

PMTiles is a single file read with HTTP range requests, so there is no tile
server to run or pay for. Three response headers make that work, and all three
are worth checking after any bucket or CDN change:

- `accept-ranges: bytes` and a `206` on a ranged GET.
- `access-control-allow-headers: range` on the preflight.
- `access-control-expose-headers` including `content-range`. Without it the
  browser hides the header the PMTiles client needs, and the map fails in a way
  that looks like a corrupt archive.

### Rebuilding

The OSM snapshot is baked into the archive (check `planetiler:osm:osmosis
replicationtime` in the metadata). Rebuild when the data is stale or the extract
area changes. Needs **Java 21**; planetiler refuses to start on 17.

```bash
brew install openjdk@21
java -jar planetiler.jar --download --area=ghana --output=ghana.pmtiles
```

Then upload to R2 and purge the Cloudflare cache for the object.

## The styles

A tile archive is only data. Nothing in it says water is blue. The style is the
document that maps the 16 vector layers onto colours, widths and label rules,
and without one a client renders an empty canvas.

Both styles are generated by `maps/build-styles.mjs` rather than hand written,
because light and dark differ only in palette, and kept apart they drift: a
layer gets added to one, the dark map quietly loses a road class, and nobody
notices until a driver is squinting at it at 6am.

```bash
node maps/build-styles.mjs      # writes maps/dist/style.{light,dark}.json
node maps/validate-styles.mjs   # checks them against the MapLibre spec
```

Validation is not optional ceremony. A malformed style does not throw, it renders
a blank grey canvas that is indistinguishable from the tiles being down. The
validator already caught one real bug: a road casing whose width wrapped a zoom
interpolation in an addition, which the spec forbids, so that layer silently
never drew.

Two things every client must get right, both encoded in the style so they are
inherited rather than reimplemented:

- **`maxzoom: 14` on the source.** The archive stops at 14. Without this MapLibre
  requests z15+, gets nothing, and goes blank exactly when a rider zooms in to
  find their stop. Vector tiles overzoom cleanly, so the map still sharpens.
- **`pmtiles://` protocol registration.** Each client registers the handler at
  startup before creating the map.

Preview them locally against the real hosted tiles:

```bash
node maps/build-styles.mjs
python3 -m http.server 8788 --directory maps   # then open /preview/
```

## Glyphs

MapLibre renders text from pre-baked SDF atlases (`.pbf` per 256-codepoint
range) fetched from the style's `glyphs` URL. There is **no fallback to system
fonts for Latin**, so missing glyphs do not mean plain-looking labels, they mean
no labels at all. That makes them part of the basemap rather than a nicety.

```bash
pnpm --filter @trotxi/maps glyphs   # writes maps/dist/fonts/
```

Built from Noto Sans (OFL-1.1, redistributable) via Fontsource, which publishes
woff2 only, so each subset is decompressed back to sfnt before fontnik slices it
into ranges. The `latin` and `latin-ext` subsets are composited per range because
Fontsource splits Latin across both and a name like "Nsawam Adoagyiri" can draw
from either.

Only `0x0000`–`0x024F` is generated (Basic Latin, Latin-1, Latin Extended-A and
-B). That covers every name in the Ghana extract; further ranges would be empty
files. Cyrillic, Greek, Devanagari and Vietnamese subsets are deliberately not
shipped for the same reason.

Two stacks, matching what the styles ask for: `Noto Sans Regular` (weight 400)
and `Noto Sans Medium` (weight 500).

## Serving it to clients

`GET /flags` carries the URLs so that changing them is a config change rather
than a simultaneous release of the rider app, the driver app and the ops console:

```json
{
  "mapTiles": {
    "url": "https://tiles.trotxi.com/ghana.pmtiles",
    "styleUrl": "https://tiles.trotxi.com/style.light.json",
    "darkStyleUrl": "https://tiles.trotxi.com/style.dark.json",
    "attribution": "© OpenStreetMap contributors · © OpenMapTiles"
  }
}
```

Any of them may be null, which means unconfigured. Clients should degrade to no
basemap rather than fail.

`attribution` travels with the URLs because it is a licence condition, not
decoration. The tiles are OSM data under ODbL and the schema is OpenMapTiles;
both require credit, and keeping them together makes it hard to ship a map
without the notice.
